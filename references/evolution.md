# 自我进化规则

本文件是 SKILL.md「自我进化」一节的展开，定义三环机制、提交流程、契约红线与命令速查。

---

## 一、设计立场：为什么不让技能自己改自己

本技能的职责是判断「产物干不干净」。如果它还能自动修改自己的判定规则，就会出现一个死结：

- 它改了规则 → 它用新规则判自己 → 它说自己合格。

这正是 SKILL.md 明令禁止的**自我合规造假**（原话：未实际执行却写出计数结论，比漏跑更严重）。所以本技能的能力边界是：

| 脚本能做 | 脚本绝不能做 |
| :-- | :-- |
| 统计数据、给建议 | 修改 SKILL.md / audit-rules.md / scan_artifact.py / scan_cross_refs.py |
| 跑回归样本、判红绿 | 自动应用自己的建议 |
| 检查契约是否完整 | 自主决定放宽或收紧判定标准 |

一句话：**脚本只有当医生的资格，没有开刀的资格。** 开刀必须由用户点头——这就是本机制的核心定性：**提案制**。

## 二、三环机制

### 环 1 · 留痕

每次自审结束，判断是否值得记录（见 SKILL.md 步骤 8）。记录写入 `logs/audit-log.tsv`，**只追加、永不覆盖**。

列定义（顺序固定，改列须同步本文件与 `evolve.py` 的 `LOG_COLUMNS`）：

| 列 | 含义 |
| :-- | :-- |
| 日期 | YYYY-MM-DD |
| 产物 | 产物名称或路径 |
| 档位 | 轻 / 常规 / 重 |
| 轮次 | 走到第几轮才达标 |
| FAIL / WARN / INFO | 确定性扫描的实测计数 |
| 得分 | 六关总分 |
| 判定 | 可交付 / 需修复后交付 / 禁止交付 |
| 误报 | 本轮被人工判定为假阳性的项数 |
| 漏报 | 本轮事后发现漏掉的项数（最高优先级信号） |
| 卡点关卡 | 未能通过的关卡名，多个用逗号分隔 |
| 备注 | 一句话说明 |

**不记流水账**：轻档单轮全 PASS 不记。记录的价值来自「异常场次」，全是 100 分的记录没有信息量。

### 环 2 · 诊断

```bash
python scripts/evolve.py --report
```

输出：记录总数、档位分布、得分趋势、机器可检项累计、人工判定的误报/漏报次数、高频卡点，以及**进化建议**。

建议的判定规则（阈值写在 `evolve.py` 的 `cmd_report`）：

| 信号 | 阈值 | 建议方向 |
| :-- | :-- | :-- |
| 误报率偏高 | 误报 /（FAIL+WARN）> 20% | 先查脚本白名单与降噪阈值，别急着加规则 |
| 出现漏报 | ≥1 次 | 优先级最高，属规则盲区，应补检查项 |
| 同一关卡反复卡壳 | ≥3 次 | 复核该关的判定口径是否过严 |
| 记录累积充足 | ≥10 条 | 可做一次完整进化评估 |

### 环 3 · 棘轮

```bash
python scripts/evolve.py --ratchet
```

跑 `fixtures/` 下 13 个单产物样本 + 2 个跨文件用例，与 `fixtures/expected.json` 逐项比对：单产物样本比 FAIL/WARN 计数与必需/排除的检查项，跨文件用例比悬空引用数。

**规则**：全绿才允许保留改动；出现任何红项即回滚。这样能挡住「修好了 A 却弄坏了 B」——2026-10-14 的 `.apk` 误报就是典型：改二进制分流时，很容易顺手把真该报的「假扩展名压缩包」一起放过去，棘轮里的 `text-with-apk-ext` 样本专门盯这一条。

样本清单与用途：

| 样本 | 盯什么 |
| :-- | :-- |
| `binary/min.zip.apk` | .apk 必须走结构分支，不得按文本硬解（原误报的回归） |
| `binary/fake.apk` | 扩展名是压缩包但内容不是，必须报结构异常（不许一放了之） |
| `binary/broken.7z` | 非 ZIP 压缩包走魔数校验 |
| `text/garbled.txt` | 整篇乱码判 FAIL |
| `text/minor_noise.txt` | 极少量坏字节不得判 FAIL |
| `prose/empty_section.md` | 空章节仍须报出（不许为降噪放掉真问题） |
| `prose/clean.md` | 干净文档零发现 |
| `prose/fenced.md` | 围栏内的井号与方括号链接不得误判 |
| `code/todo.py` | 源码里的真实待办照常报，语法符号不误报 |
| `naming/copyright.md` | 文件名含 copy 但非独立成词，不得判副本 |
| `structured/broken.json` | 结构化文件语法校验：裸引号让整份配置解析失败，必须报出（原零检出） |
| `structured/valid.json` | 合法 JSON 不得误报（新增语法校验后的零发现回归） |
| `naming/placeholder-name.md` | 谈论「名字」的句子里的占位词属模板说明，须降噪 |

新增样本的步骤：① 在 `fixtures/_generate.py` 里加生成代码 → ② 跑 `python fixtures/_generate.py` → ③ 实测确认期望值（不许凭猜）→ ④ 写入 `expected.json`。

**跨文件用例**（`expected.json` 的 `xref_cases`，样本在 `fixtures/crossrefs/`）：

| 用例 | 盯什么 |
| :-- | :-- |
| `xref-dangling-detected` | 真断链必须报出（2 条），同时不得把元描述与强调引号算作悬空 |
| `xref-clean-zero` | 全部可达时零悬空——降噪不能过头，否则该报的也会被一并放掉 |

为什么跨文件也要回归：`scan_cross_refs.py` 的降噪判据很敏感（筛子过紧会漏报真断链、过松会满屏假悬空），首版上线当天连踩两次，全靠样本才定住行为。新增用例步骤同上，期望值字段写 `expect_dangling`（悬空引用数）。

## 三、契约红线

以下五项被**外部载体**直接引用，属对外接口，改动即牵连别处：

| 契约 | 被谁引用 |
| :-- | :-- |
| 六关名称与顺序 | 外部工作流约定与 agent 自定义指令（引用本技能检查流程的条目） |
| 轻 / 常规 / 重三档及门槛 | agent 自定义指令（"按档位要求连续通过"的条目） |
| 自审状态标记格式 | 外部工作流强制条款（每次回答末尾必须出现） |
| `references/audit-rules.md` 路径 | agent 自定义指令（"退回按该技能 references/audit-rules.md 六关规则手工执行"的条目） |
| `scripts/scan_artifact.py` 的 CLI | 技能自身步骤 3 的调用示例 |

随时可自查：

```bash
python scripts/evolve.py --contract
```

15 项逐条打 OK/缺失；有缺失即接口破坏，必须在交付前修复。

**未进入契约的新脚本（v1.4.0）**：`scripts/scan_cross_refs.py`（跨文件引用可达性 + 同主题对照）目前只被本技能自身引用，**暂不属契约**。若日后外部记忆文件或自定义指令也开始调用它，须把它的 CLI 升格为契约项并走 major 版本。

**两个脚本的分工**：`scan_artifact.py` 管「单个产物本身干不干净」；`scan_cross_refs.py` 管「多载体之间是否自相矛盾、引用是否落到实处」。两者互补、不得互相替代——这正是 2026-10-15 那次漏报的教训：语义矛盾与断链引用两类问题，单产物视角天生看不见。

## 四、版本与改动流程

版本语义：

| 改动性质 | 版本递增 | 是否需同步外部载体 |
| :-- | :-- | :-- |
| 措辞、阈值微调 | patch（1.4.x） | 否 |
| 新增检查项 / 新机制 / 新样本 | minor（1.x.0） | 否 |
| 改动契约红线任一项 | major（x.0.0） | **必须**同步所有引用该契约的外部载体 |

改动六步流程：

1. `--report` 明确缺口
2. 写提案 `logs/proposals/YYYY-MM-DD-主题.md`（改什么 / 为什么 / 预期效果 / 影响面）
3. 等用户确认（未确认不动文件）
4. 改文件
5. `--ratchet` + `--contract` 双验证，两个全绿
6. 记 `CHANGELOG.md`、递增版本号

若第 3 步的改动涉及 ≥2 个载体、或改动与你的工作流/记忆文件存在对应记录，还要按你自己的跨载体一致性复查约定再跑一轮（重点：引用可达性、语义矛盾两项）。

## 五、命令速查

```bash
# 统计与建议
python scripts/evolve.py --report

# 棘轮回归（改完必跑）
python scripts/evolve.py --ratchet

# 契约检查（改完必跑）
python scripts/evolve.py --contract

# 跨文件检查（改动涉及 ≥2 个载体、或与你的工作流/记忆文件存在对应记录时；检出悬空引用则退出码 1）
python scripts/scan_cross_refs.py [--files ...] [--keywords 词1 词2 ...]

# 追加一条留痕
python scripts/evolve.py --append --date 2026-10-14 --artifact "<产物>" --tier 常规 \
  --rounds 1 --fail 0 --warn 2 --info 1 --score 100 --verdict 可交付 \
  --fp 0 --miss 0 --stuck "" --note "<备注>"

# 重建全部回归样本（改了 _generate.py 之后）
python fixtures/_generate.py
```

退出码约定：`0` 通过、`1` 发现问题、`2` 用法或环境错误。

## 六、设计来源

三环结构参考了 Karpathy 的 autoresearch 思路（评估 → 改进 → 实测验证 → 保留或回滚的棘轮），以及与 darwin-skill 的差异：

- darwin-skill 优化的是**技能文件本身**，用 8 维主观 rubric 打分，允许自动 hill-climbing；
- 本机制优化的是**自审技能的判定可靠性**，用确定性样本（可复现、无主观）判红绿，且**不允许自动改动**。

即：darwin 是教练，本机制是体检仪——教练可以建议换动作，体检仪只能报数值。
